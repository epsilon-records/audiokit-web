Get started

Run your first job

AudioKit works in jobs. You send a link to a file and the operation you want; AudioKit checks the file, runs the operation and sends the result to your webhook.

{{BASE_URL_NOTE}}

Before you start

  • An API key. Create an AudioKit account or sign in — the console shows your first key once when you sign in, and lists it under API keys. Keys look like ak_….
  • A file AudioKit can download. An https URL to it, usually a signed GET URL from your storage. It must resolve to a public address, including after redirects.
  • The file's sha256. Hash the exact bytes your URL serves, for example with sha256sum master.wav.
  • Optional: a webhook endpoint. An https URL that accepts POST. Without one, you poll for the result.

Submit a job

This measures a file's loudness. job_id is yours: use something you can look up later. It's also the idempotency key.

shell
curl {{API_BASE}}/v1/jobs \
  -H "Authorization: Bearer $AUDIOKIT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "job_id": "job-0193",
    "operation": "loudness",
    "input": {
      "url": "https://storage.example.com/master.wav?signature=abc",
      "sha256": "837d2e9c0f1a4b5c6d7e8f9012a3b4c5d6e7f8091a2b3c4d5e6f708192a3b4c5",
      "filename": "master.wav"
    },
    "webhook": { "url": "https://you.example/audiokit/webhook" }
  }'

You get 202 Accepted and the job, with status: "queued" and AudioKit's own provider_job_id. Keep that ID: it's how you fetch or cancel the job.

Other operations work the same way. Some take params; the reference lists them for each operation.

Get the result

When the job finishes, AudioKit POSTs a job.succeeded, job.failed or job.canceled event to your webhook, with the job as data. You can also fetch the job at any time:

curl {{API_BASE}}/v1/jobs/$PROVIDER_JOB_ID \
  -H "Authorization: Bearer $AUDIOKIT_KEY"

Verify webhooks

Every event carries X-Signature: t=<unix seconds>,v1=<hex>, an HMAC-SHA256 of "{t}.{raw_body}" keyed with your webhook secret. Verify it against the raw body before parsing, and reject timestamps more than 300 seconds old.

Node
import crypto from "node:crypto";

export function verify(secret, rawBody, header, now = Date.now() / 1000) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const t = Number(parts.t);
  if (!t || Math.abs(now - t) > 300) return false;
  const mac = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex");
  return mac.length === parts.v1?.length &&
    crypto.timingSafeEqual(Buffer.from(mac), Buffer.from(parts.v1));
}
Python
import hashlib, hmac, time

def verify(secret: bytes, raw_body: bytes, header: str, now: float | None = None) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(",") if "=" in p)
    t = int(parts.get("t", 0))
    if not t or abs((now or time.time()) - t) > 300:
        return False
    mac = hmac.new(secret, f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, parts.get("v1", ""))

Check your code against this vector. Its timestamp is fixed, so pass now as 1793440800 when testing with it.

Reply with any 2xx to acknowledge. Otherwise AudioKit retries after 10 s, 1 min, 5 min, 30 min, 2 h and 6 h, then stops; the job itself always has the final state. Each event has a unique event_id: ignore ones you've already handled.

Retries and idempotency

If a submit times out, send the same request again. The same body with the same job_id returns the existing job with 200, so nothing runs twice. The same job_id with a different body is refused with 409 idempotency_conflict. To process a file again, use a new job_id.

Operations that write files

transcode and preview write a new audio file. Give AudioKit somewhere to put it: a signed PUT URL in outputs.audio, with any headers the signature needs. AudioKit sets Content-Type and Content-Length itself.

request body
{
  "job_id": "job-0194",
  "operation": "preview",
  "input": { "url": "https://storage.example.com/master.wav?signature=abc", "sha256": "837d2e9c…" },
  "params": { "duration_seconds": 30 },
  "outputs": {
    "audio": {
      "url": "https://storage.example.com/upload/preview.mp3?signature=def",
      "headers": { "x-upsert": "true" }
    }
  },
  "webhook": { "url": "https://you.example/audiokit/webhook" }
}

The result reports the uploaded file's sha256 and size_bytes. Hash what you stored and compare.

Cancel a job

POST /v1/jobs/{provider_job_id}/cancel. A queued job is canceled at once (200). A running job is asked to stop (202) and a job.canceled event follows. A finished job comes back unchanged (200).
