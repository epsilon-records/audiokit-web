# Site audit: accessibility, performance and SEO

Audit of the audiokit.ai static site (`src/pages/`, `scripts/build.mjs`, `src/static/`) against
WCAG 2.1 AA, Core Web Vitals basics and technical SEO. The Console direction is unchanged.

Method: read the source and built `dist/` HTML, measured the dark-theme colour tokens with the
WCAG contrast formula, and ran structural checks (landmarks, heading order, duplicate ids, image
`alt`, form labels) over every built page. `npm test` and `npm run build` both pass.

## Already good

- **Landmarks**: one `<main id="main">` per page, a working skip link, and `aria-label`ed header,
  footer and docs-sidebar `<nav>`s.
- **Headings**: exactly one `<h1>` per page and no skipped levels (checked on all 7 built pages).
- **Logo**: the inline SVG is decorative (`aria-hidden="true"`) with the visible "AudioKit" text as
  the accessible name, plus explicit `width`/`height`.
- **Focus**: visible `:focus-visible` outline on links, buttons, inputs and `summary`.
- **Contrast**: every text token passes AA. Lowest measured pair is the input placeholder
  (`#7e8792` on `#0c0e11`, 5.31:1); body and muted text are 7.5:1–15.7:1.
- **Images**: no `<img>` elements; nothing needs `alt`.
- **Ids**: no duplicate ids on any page.
- **Fonts**: `display=swap` with `preconnect` to both Google Fonts hosts, so text is not blocked.

## Fixes landed

1. **Canonical and social metadata** (`scripts/build.mjs`): added `<link rel="canonical">`,
   `og:url`, `og:site_name`, `og:locale` and Twitter card/title/description tags. Canonical and
   `og:url` are omitted on `noindex` pages (`/404.html`, `/thanks/`). URLs are absolute against the
   new `siteUrl` in `site.config.mjs`, so Netlify deploy previews don't compete with production.
2. **`sitemap.xml` and `robots.txt`** are generated by the build from the indexable pages (5 URLs)
   and written to `dist/`.
3. **`color-scheme: dark`** set in both a meta tag and `:root`, so native form controls,
   scrollbars and the pre-CSS background match the dark theme.
4. **Unused JS removed per page**: `site.js` (copy buttons, "On this page" collapse) is now only
   emitted on pages that contain those elements, i.e. the docs pages. The landing, pricing, 404
   and thanks pages no longer load it.

## Known gaps (not fixed here)

- **No `og:image`.** A social preview needs a real raster (1200×630 PNG/JPG); SVG is not reliably
  supported by the crawlers. Left for a design task so the tag points at an asset that exists.
- **Form labels are programmatic only.** The access form's labels are `sr-only` and the
  placeholder is the only visible prompt; native validation supplies the error text. Showing
  visible labels would change the layout, so it is left as a design decision.
- **Fonts come from Google Fonts** (a third party). Self-hosting the two families would shave the
  connection setup and give tighter control over layout shift, but needs font binaries and their
  licenses committed to this repo.
- **Landing-page description is 236 characters**; search engines will truncate it. Rewriting it is
  a copy decision.
